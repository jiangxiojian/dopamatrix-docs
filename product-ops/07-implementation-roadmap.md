# 实施路线图

> 更新时间：2026-07-27  
> 状态：规划草案

## 原则

不要一次性把所有想法都做完。接下来的层次应该围绕一条共享数据主线，按模块逐步展开。

```text
client_id
product_id
asset_batch_id
creative_id / video_id
gene_version
account_id
publish_id
platform_post_id
attribution_token
lead_id
report_snapshot_id
```

如果这些 ID 统一，发布、询盘、报告和爆款学习就能分阶段实现，而且不会丢历史。

## 阶段 0：数据主线与规划表

目标：在做发布自动化前，先把最低限度的数据结构准备好。

需要的表：

- `clients`
- `products`
- `asset_batches`
- `creative_gene_snapshots`
- `platform_accounts`
- `publish_plans`
- `publish_logs`
- `attribution_tokens`
- `leads`
- `metric_snapshots`

关键规则：

- 客户数据必须按 `client_id` 隔离。
- 每次发布都必须有稳定的 `publish_id`。
- 每个公开帖子都尽量保留 `post_url` 和 `platform_post_id`。
- 每个 token 都必须绑定一条发布记录。

## 阶段 1：TK + FB 发布试点

目标：用脚本辅助，完成 TikTok 视频和 Facebook Page 图文帖的双平台发布闭环。

范围：

- 导入交付目录和 CSV。
- 建立发布计划表。
- 绑定 2-3 个 TikTok 账号和 2-3 个 Facebook Page 管理环境到指纹浏览器环境。
- 通过比特浏览器打开环境。
- TikTok 上传视频并填写 caption。
- Facebook Page 上传图文素材并填写正文。
- 停在人工确认点。
- 保存截图和状态。
- 记录帖子链接。

成功标准：

- 3-5 条 TikTok 视频通过辅助流程成功发布。
- 3-5 条 Facebook Page 图文帖通过辅助流程成功发布。
- 失败原因是结构化的。
- 次日账号还能正常复登。
- 运营人员不用靠记忆也能复现流程。

## 阶段 2：账号台账与风险控制

目标：在扩量前先让账号体系不乱。

范围：

- 账号所有权类型：自有还是客户。
- 按地区/品类/客户划分账号池。
- 绑定浏览器环境。
- 记录代理/地区。
- 记录每日发布上限。
- 记录账号健康状态。
- 记录异常日志。

成功标准：

- 没有任何账号在没有台账记录的情况下被操作。
- 共享账号的客户路由是显式的。
- 即使暂时不用，客户账号的风险字段也已经存在。

## 阶段 3：询盘归因 MVP

目标：证明询盘来自哪里。

范围：

- 每条发布记录生成 `attribution_token`。
- 支持人工录入或导入线索。
- 绑定线索到帖子、账号、产品和客户。
- 记录归因可信度。
- 记录线索状态。
- 导出客户专属线索报告。

成功标准：

- 客户能看到每条线索的来源帖子和证据。
- 共享账号下的模糊线索可以先留在待确认池。
- 有效、无效、重复、已报价、已成交都能记录。

## 阶段 4：客户报告网页

目标：先让客户可以随时查看发布结果。

范围：

- 总览面板。
- 内容与发布列表。
- 帖子链接、发布状态和待补指标。
- 基础发布表现指标占位。
- 周报/月报导出。
- 数据同步时间和来源标签。

成功标准：

- 客户能看到自己的发布内容、帖子链接和状态。
- 共享账号总量不会被重复算给多个客户。
- 报告能区分已发布、待补链接和待补指标。

后续完整门户再加询盘列表、客服流转和创意洞察。

## 阶段 5：爆款基因闭环

目标：让内容生产根据结果学习。

范围：

- 在生成时保存 `gene_snapshot`。
- 把帖子指标和线索绑定到基因。
- 标记赢家和失败者。
- 追踪创意谱系。
- 建立外部参考库。
- 给下一批内容提供实验建议。

成功标准：

- 能用结构化基因解释表现最好的帖子。
- 新变体能说明保留了哪些基因、改了哪些基因。
- 洞察会标记为观察到、测试中或已验证。

## 阶段 6：平台扩展

等 TikTok + Facebook 试点稳定后再扩展。

可能顺序：

1. 账号权限路径清晰的 Instagram。
2. YouTube Shorts 或其他视频平台。
3. 其他平台，前提是 API 或浏览器流程已验证。

每个平台都要单独补：

- 账号台账字段。
- 发布适配器。
- 指标映射。
- 线索来源映射。
- 平台政策和人工检查点。

## 以后再做

- 自动多平台发布。
- 完整的私信抓取。
- 带 OSS 的客户上传门户。
- 成本、收入和 ROI 看板。
