## 目标与范围

让运营提前核对并批准一批任务后，脚本自动上传、设置封面、填写文案、立即提交或提交定时发布，记录结果和异常。正常任务无需逐条守候；平台验证、账号异常和不明确的提交结果进入人工处理。

第一版范围限定为 TikTok 视频、Facebook Page 图文，以及逐一验证过的 Page 视频/Reels 入口。Facebook 个人主页、快拍、复杂封面编辑和大规模并发后置。不同平台、账号类型和入口的封面/排期能力必须分别验证，不能由一个入口推断另一个也支持。

工作起点是“投放包已准备完整”。内容生成和交付包制作由主产品流程负责，本专项继续在 `docs/scripts/publishing` 实施。发布仍通过 BitBrowser Local API 和浏览器页面操作完成；官方发布 API 接入单独评估。

## 当前代码基础

| 能力 | 当前实际状态 | 自动发布阶段需要补齐 |
| --- | --- | --- |
| 账号与素材 | 可读台账、选择账号/窗口、导入投放表并增量刷新 | 核对实际网页登录账号和目标 Page，不能只相信台账名称 |
| 发布入口检查 | 工作台后台读取目标窗口的现有同平台页面，保存上传、封面、定时和提交控件的可见线索 | 当前只观察，不核验登录身份、不操作控件、不证明提交或定时成功 |
| 上传与文案 | 可上传 TK 视频、FB 图片及基础视频/Reels 草稿，填写文案 | 等待平台媒体处理完成，核验预览及文案确实生效 |
| 封面 | 工作台可导入/选择本地 JPG/PNG/WebP、预览并绑定任务；扫描排除 `covers/` | 真实平台封面应用、指定视频帧及适用入口核验仍待实现 |
| 最终提交 | 当前始终停在人工发布前 | 新增经批准任务的自动立即发布/定时提交分支 |
| 排期 | 工作台可保存日期/时区预设并换算 UTC，拦截过去及夏令时歧义时间；旧 `scheduled_at` 仍为记录字段 | 预设不触发执行，不表示平台接受排期；原生定时提交及回执仍待实现 |
| 内容确认 | 可预览选中任务、后台计算文件指纹并整批保存确认；内容变更显示失效 | 当前仅记录内容审核，不能作为已启用自动提交的授权；执行时的强校验和完整提交状态机仍需接入 |
| 队列 | 已有顺序执行、单任务硬超时和单服务内防重复 | 持久恢复、暂停、跨 EXE 互斥、提交结果不明时的恢复策略 |
| 结果与报告 | 已有截图、日志、手工回填、链接识别和报告基础版 | 区分已排期、审核中与已发布，可靠关联本条任务，避免抓取旧作品 |
| 通知 | 尚无结束/异常主动通知 | 完成摘要和需介入异常通知，明确负责人及恢复入口 |

当前已增加入口观察、发布设置预设和内容确认，并纳入 2026-11-22 打包版；其余自动执行能力仍为计划，EXE 不具备自动发布或真正的定时功能。

## A1 前置配置与内容确认

| 功能 | 当前实现 | 边界 |
| --- | --- | --- |
| 发布模式与设置 | 人工确认、自动立即发布预设、平台定时预设；可见范围及商业/AI 内容三态声明 | 仅保存设置，不应用到浏览器；未指定声明不等于选择“否”，自动执行前还需逐入口校验 |
| 封面导入与预览 | JPG/PNG/WebP，8 MB 上限，验证实际图片格式和尺寸；复制到包内 `covers/` 并按内容摘要命名，选择后预览、保存 | 只绑定本地封面，尚未上传到 TK/FB；图片帖不另设视频封面，指定视频帧后续实现 |
| 时间及时区 | 明确当地时间和 IANA 时区，计算 UTC；拦截过去、跳时和重复时段 | 预设存于设置文件，不写成“平台已排期”，也不启动本地计时器；平台预约范围和提前量仍待实测 |
| 批次内容确认 | 勾选任务后展示账号、素材路径、标题/文案/标签、短链、封面、设置及时间；填写确认人后后台校验整批 | 文件或任务在预览后变化时拒绝旧版本；任一项失败不写入部分确认，不上传、不提交 |
| 变更失效与强校验基础 | 根据当前计划、对应文案行、账号/窗口、设置及文件状态判断确认是否过期；保存 SHA-256，提供完整内容校验函数 | 列表采用文件路径/大小/修改时间快速核对，未来执行前必须调用完整指纹核验，不能拿列表的“已确认”直接提交 |

设置与确认自动保存到计划目录的 `publish_options.json`，新包为 `rpa_work/publish_options.json`；普通运营不需要维护新表。保存设置支持版本校验，防止旧网页覆盖新设置；修改设置使旧确认失效，改回原选项也需重新确认。对应文案行变化后，先“刷新投放表”、核对新内容，再确认；新增其他素材不会使原任务的确认失效。

已有草稿或发布记录的任务锁定设置，先处理原页面再加入重试队列。确认期间同一工作台服务禁止准备、改设置、改账号和重复启动，网页刷新能继续查看进度；不等于跨 EXE 锁、重启后恢复正在计算的批次或完整审核历史。确认结果在正常程序重启后可读取。设置/确认都不改变发布状态、帖子链接或已排期/已发布统计。

本组开发以临时数据验证，没有访问 001/002，也未上传或发布。A0 未验收的真实入口保持未验收；A1 与平台无关的前置配置可并行开发，实际自动提交仍需等待相关入口及执行保护完成。

工作台检查读取当前同平台标签页，入口不在当前页面时显示“未发现”，不能据此认定平台不支持。多个编辑页或 Page 候选会提示核对目标；总览证据不能作为某一发布入口已验收的结论。当前报告始终将身份核验、自动发布验证标为未完成。

检查记录默认位于 `rpa_work/entry_checks/`，只保存控件线索、脱敏页面路径和结果，不改发布计划、发布状态或链接，也不写入发布成功日志。结果绑定任务、账号、窗口、内容类型及入口，分配变更后不复用其他窗口的检查结果。开发实机截图和面板检查记录放在忽略版本管理的 `scripts/publishing/build/entry-check-001/`。

## 运营流程

```text
导入完整投放包
-> 核对实际账号/Page、素材、文案、封面和发布设置
-> 选择人工确认 / 自动立即发布 / 定时发布
-> 核对本批任务及时间，批准执行
-> 队列自动准备并提交
-> 已排期 / 审核中 / 已发布 / 异常待处理
-> 回收链接、记录结果并生成报告
```

选项在 EXE/工作台中操作并持久保存，普通运营不需要新增手工 CSV 表或输入命令。原有人工模式继续可用，新任务默认使用人工模式。

| AUTO-02 | P0 | 发布前校验 | 实际账号/Page 与任务一致、素材可预览、文案/标签填写生效、媒体处理完成、按钮可用后才提交。未知提示或校验不明确时暂停，固定等待几秒不能作为成功依据。 |

| AUTO-05 | P0 | 平台原生定时 | 在支持的入口设置日期、时间和时区，校验平台允许的提前量、最远时间、数量等限制；提交后核实平台排期记录/回执。无此能力的入口不得显示已完成定时。 |
| AUTO-06 | P0 | 发布成功与结果回收 | 分开记录点击提交、平台接收、已排期、审核中、已发布和失败。保存可取得的回执/任务 ID、帖子 ID、链接和时间；没有可靠证据时保留待核查状态，不把点击或上传成功算作已发布。 |
| AUTO-07 | P0 | 防重复与审批失效 | 提交前持久记录任务与内容版本；提交后超时、断网或 EXE 退出先核查平台记录，再决定下一步。改素材、文案/标签、封面、账号/Page、发布设置或排期后，原批准失效。 |
| AUTO-08 | P0 | 队列、暂停和恢复 | 持久保存任务及执行进度，重启后恢复未完成任务；同一比特窗口顺序执行，并补跨 EXE 的计划/窗口互斥。安全暂停以完成当前步骤或明确记录中断位置为准，不能假定按暂停即撤回平台提交。 |
| AUTO-09 | P0 | 异常隔离和通知 | 登录失效、验证码、人脸验证、代理异常等暂停相关账号；其他账号按已配置规则继续或暂停。准备阶段允许有限重试，提交结果不明禁止盲目重试。提供工作台异常列表及配置后的完成/异常通知，负责人可定位任务和证据。 |
| AUTO-10 | P1 | 完整投放包自动接收 | 约定交付完成标记或原子交付方式，避免文件还在复制时导入；识别重复包与更新包。新增/变更任务进入待批准队列，不能继承旧批次的批准。 |
| AUTO-11 | P1 | 本地定时备用方案 | 软件到点打开环境并执行；明确电脑唤醒、程序/BitBrowser 在线与网络要求。持久保存任务，提供逾期跳过/人工确认/限定范围补发策略；默认不在恢复后集中补发所有过期任务。 |

AUTO-06 包含链接自动回收的进一步可靠性改进；现有识别器是基础，不应直接等同于自动发布验收通过。原生定时尚未到点时，公开帖子链接可以为空，排期回执应单独记录。

## 封面实现约定

第一版做基础封面，不做在线设计工具。运营可保留默认封面、选择已有图片，或填写视频帧时间并查看预览；各模式按入口实测结果开放，完整三种模式不能预先承诺每个平台都支持。

本地封面已集中到投放包的 `covers/`，任务设置保存相对路径；截图等执行产物仍放 `rpa_work/`。素材扫描已排除 `covers/`，避免封面误生成 FB 图文任务；未来抽帧预览也应放在工作目录并排除扫描。封面与任务明确绑定，替换封面内容需重新确认。

选定帧应校验非负、位于视频时长内；本地上传封面应验证文件存在及平台要求。优先通过平台可用的选帧功能实现；本地抽帧只负责生成封面图片，不代表平台支持上传自定义封面。

## 定时路线与时间口径

| 路线 | 执行方式 | 成功证据与运行条件 |
| --- | --- | --- |
| 平台原生定时，优先 | 提前上传并把发布时间提交给 TK/FB | 核实平台已保存的目标账号、内容和排期时间；平台接受后通常由平台到点执行，不依赖本地 EXE 一直在线。后续可能审核失败，仍需回收最终状态。 |
| 本地定时，备用 | 本地队列到指定时间再打开浏览器执行 | 电脑、EXE、BitBrowser 和网络需可用；睡眠、锁屏、重启、断网及错过时间都要验证。没有原生定时能力时，不自动改成本地定时，需运营明确选择。 |

运营界面同时展示日期、时间和明确时区。计划保存带时区的时间，调度统一比较 UTC；目标地区有夏令时时，需要处理重复/不存在的本地时间。区分“开始准备时间”“计划公开时间”“平台接受排期时间”和“实际发布时间”，并预留上传处理时间。

第一轮实机验证应记录各账号/入口支持情况及限制，不硬编码未验证的预约天数或最短提前量。已提交到平台的排期，修改或取消时必须核实平台实际结果，不能只改本地 CSV；无法自动修改/撤销时转人工处理。关闭本地队列不会自动取消平台已接受的排期。

## 内容版本、结果状态与重试

批准内容应包含素材文件指纹、文案/标签、封面、平台账号/Page、发布设置、发布模式及排期。文件路径相同但内容被替换，也应被识别为变更。批准人、批准时间和内容版本要可回查；客户端刷新表格后不能悄悄把已批准的旧内容替换成新内容继续自动提交。

建议区分以下业务状态，具体字段名在实施时与已有 CSV/JSONL 和报告口径对齐：

| 建议状态 | 含义与处理 |
| --- | --- |
| 待批准 / 已批准 | 已导入任务与获准自动执行分开；普通 READY 不表示已批准 |
| 准备中 / 已准备 | 上传和填写阶段；人工模式仍在此等待人工发布 |
| 提交中 | 点击最终按钮前先持久记录，防止退出后误当作未执行 |
| 结果待核查 | 提交后断网、超时或没有可靠回执；停止重复提交，查询平台记录或交人工 |
| 已排期 | 平台已接受未来发布计划；尚未计入已发布数量 |
| 审核中 | 平台正在审核，后续可能通过或拒绝；不因等待就自动重发 |
| 已发布 | 有与本次任务可靠关联的发布证据，记录可取得的帖子 ID、URL、实际时间 |
| 异常待处理 / 已取消 | 保存原因、证据及下一步；本地取消与平台撤销结果分别核实 |

链接回收需结合本次提交记录、账号、时间、帖子 ID 及可取得的内容信息建立关联；“列表最上方的作品”不能单独成为匹配依据。无法唯一对应时保留待核查，不用旧帖填充新任务。报告必须分开统计已排期、审核中、已发布、失败和待核查；发布成功也不代表获得推荐或播放。

P0 表示自动发布首版的必要能力。A0 入口验证与 A1 的本地前置配置可并行推进，实际自动提交需相关入口验收及执行保护齐全；随后接入 A2。A3 不阻塞人工导入投放包后使用自动发布。不同入口可分批验收，未验证的模式保持关闭。

## 验收样本与运行边界

| 场景 | 必须确认的结果 |
| --- | --- |
| 正常自动立即发布 | 指定账号、素材、封面、文案和设置正确，仅提交一次并取得对应证据 |
| 正常原生定时 | 时区和平台时间一致，先记录已排期，到点后另行核对实际状态 |
| 提交前失败 | 不误报已发布；有限重试或暂停，其他账号按既定规则处理 |
| 点击后断网、超时、EXE 退出或同时启动两份 EXE | 恢复时先核查平台结果，同任务和窗口不能被重复提交 |
| 批准后修改 CSV、替换素材/封面、改账号/Page 或时间 | 批准失效，变更可见，重新批准后才可执行 |
| 已排期后修改或取消 | 本地与平台结果分别核实，平台未撤销时仍显示原排期及待处理原因 |
| 登录失效、验证码、人脸验证或未知必选提示 | 暂停相关账号，保存证据并提示人工，不能无限重试或猜选 |
| 历史视频与本次视频同时存在 | 帖子链接唯一关联本次任务；不能确认时保持待核查 |
| 默认封面、本地图片、视频帧和不支持的模式 | 支持的模式预览与平台实际结果一致；不支持的模式明确停止并提示 |

先用模拟发布和离线故障测试覆盖状态机，再针对指定测试内容安排实际提交验收；真实发布按已明确批准的测试批次执行。封面、定时和异常恢复未验收前，不宣称具备完整夜间无人值守能力。

平台验证、安全限制和账号状态问题交人工处理；自动化不提供推荐量、播放量或账号可用性的保证。异常通知需明确接手人和处理时段；无法及时接手时任务保持暂停。

复杂封面编辑、自动注册/养号、刷量、绕过验证、询盘客服、客户权限门户和爆款基因不纳入本首版。账号与网络异常继续独立排查，不能以增加自动发布功能代替。
