## DEC-20260727-003：试点阶段优先运营自有账号

| 字段 | 内容 |
| --- | --- |
| 状态 | 已决策 |
| 日期 | 2026-07-27 |
| 背景 | 客户交账号会带来授权、误发、封禁、数据归属和合同风险。 |
| 决策 | 试点阶段优先运营自有账号。客户账号模式先在数据模型中预留，通过正式平台授权后再扩展。 |

| 后续 | 起草客户账号授权和风险边界清单。 |

## DEC-20260727-004：共享账号必须透明定位为垂直品类号

| 字段 | 内容 |
| --- | --- |
| 状态 | 已决策 |
| 日期 | 2026-07-27 |
| 背景 | 一个账号服务多个客户时，相似产品容易造成用户、客服和甲方归因混淆。 |
| 决策 | 共享账号只能作为垂直品类号、经销商号、选品号或媒体号，不伪装成单一客户品牌号。 |
| 影响 | 主页链接应使用透明目录页；询盘需要先确认产品再分配。 |
| 后续 | 定义共享账号目录页和模糊询盘处理规则。 |
| 相关文档 | [02-account-strategy.md](./02-account-strategy.md), [03-lead-attribution-and-service.md](./03-lead-attribution-and-service.md) |

## DEC-20260727-005：每条发布记录必须生成 attribution_token

| 字段 | 内容 |
| --- | --- |
| 状态 | 已决策 |
| 日期 | 2026-07-27 |
| 背景 | 如果视频发出后再补归因，很多询盘无法证明来自哪个账号、帖子、客户和产品。 |
| 决策 | `attribution_token` 在发布计划阶段生成，并绑定到唯一 `publish_id`。 |
| 影响 | 发布、询盘、报告和短链都应使用同一条归因链。 |
| 后续 | 在发布计划表和线索表中加入 token 字段。 |
| 相关文档 | [03-lead-attribution-and-service.md](./03-lead-attribution-and-service.md), [07-implementation-roadmap.md](./07-implementation-roadmap.md) |

## DEC-20260727-006：任务清单里的落地页不是客户商品落地页

| 字段 | 内容 |
| --- | --- |
| 状态 | 已决策 |
| 日期 | 2026-07-27 |
| 背景 | 讨论中曾把“落地页”理解为客户商品承接页，后续澄清这是 DopaMatrix 产品宣传获客页。 |
| 决策 | DopaMatrix 产品宣传页与客户导流目录页分开。客户导流能力归入询盘归因和客服体系，不混进宣传页任务。 |
| 影响 | 报告、账号主页链接和询盘入口不能被错误归到“产品宣传落地页”任务。 |
| 后续 | 如需客户导流目录页，后续单独设计为归因组件。 |
| 相关文档 | [README.md](./README.md), [02-account-strategy.md](./02-account-strategy.md) |
