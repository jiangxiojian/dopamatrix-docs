# 账号策略

> 更新时间：2026-07-27  
> 状态：规划草案

## 核心判断

账号问题不只是“注册账号”。它是账号资产体系：

```text
账号 -> 浏览器环境 -> 代理/地区 -> 内容权限 -> 客户/产品归属
-> 发布能力 -> 风险状态 -> 询盘承接 -> 报告归因
```

账号策略必须先于发布自动化明确，因为它直接影响询盘归属、客户报告、平台风险和后续客服。

## 账号所有权模式

| 模式 | 适用场景 | 优点 | 风险 |
| --- | --- | --- | --- |
| 自有垂直账号 | 早期试点、品类内容、多客户验证 | 便于统一运营和标准化 | 平台风险由我们承担，账号定位必须透明 |
| 客户品牌账号 | 成熟客户、品牌独占运营 | 甲方信任度高，粉丝归客户 | 法务、安全、授权和误操作风险更高 |
| 客户正式授权资产 | Facebook Page、Business Suite、TikTok 企业流程等 | 权限边界比共享密码清晰 | 需要客户配合和合同约定 |
| 共享密码代运营 | 不建议 | 前期快 | 安全、争议、验证、合作终止都高风险 |

当前建议：试点阶段先运营自有账号。数据模型提前支持客户账号，但不要在授权、合同和 SOP 没准备好时把客户账号作为默认模式。

## 共享账号原则

一个账号可以服务多个客户，但前提是它本身被清楚定位为垂直品类号、经销商号、选品号或媒体号。

可接受定位：

```text
卫浴选品号
家居供应链观察号
海外工程采购参考号
```

不建议：

- 共享账号伪装成某个甲方的官方品牌号。
- 同账号服务直接竞争对手。
- 高度相似产品混在一起，却没有明确分流和客服规则。
- 把共享账号的全部播放、粉丝和询盘重复算给多个甲方。

## 账号分配

账号池可以按以下维度管理：

- 客户。
- 地区。
- 语言。
- 产品品类。
- 风险等级。
- 账号成熟度。

早期尽量避免同一个账号服务多个高度相似产品。如果不得不做，每条帖子必须绑定：

```text
account_id
platform_post_id
client_id
product_id
publish_id
attribution_token
```

## 主页链接怎么挂

如果账号只属于一个客户，主页链接可以指向客户官网、店铺或官方 Lead Form。

如果账号服务多个客户，主页不能挂某一个客户的链接，应使用透明的账号级目录页：

```text
账号主页链接 -> 品类目录页 -> 产品/SKU -> 客户/销售分配
```

目录页必须让用户知道这里是多产品或多品牌入口，不能伪装成单一品牌官网。

同时要注意：主页链接只能解决通用入口问题，不能替代帖子级归因。每条视频仍然必须绑定 `post_id -> product_id -> client_id`。

## 什么时候加账号

不要因为需求一来就立刻加账号。新增账号应基于账号池容量和稳定性。

观察指标：

- 7 天发布成功率。
- 次日复登成功率。
- 验证码/安全验证频率。
- 内容审核通过率。
- 帖子是否正常可见。
- 询盘处理压力。
- 发布排期占用率。

实操触发线：某个账号池连续几天达到约 70% 的安全发布和客服承载能力，就提前准备新账号，而不是等账号彻底超负荷。

## 账号养成

不要把“养号”理解成模拟行为或刷互动。更稳的账号建设方式是：

- 使用合法身份和联系方式注册。
- 绑定稳定邮箱/手机号、恢复方式和二次验证。
- 地区、语言、代理和浏览器环境保持一致。
- 完成头像、简介、联系方式和业务定位。
- 初期保持正常内容节奏，并人工审核。
- 不批量发布完全重复视频。
- 不刷粉、不刷赞、不刷评论、不做互相虚假互动。
- 不自动绕过验证码或安全检查。
- 记录登录、发布、异常和恢复动作。

不存在可靠的“养满 N 天就安全”。只能通过账号健康数据逐步判断。

## 主号、小号、大号

账号可以分层，但应按业务角色分层，而不是做虚假流量。

| 层级 | 角色 |
| --- | --- |
| 测试号 | 测试内容角度和平台流程。 |
| 成长号 | 承接稳定发布量。 |
| 主号 | 发布更高质量、更品牌敏感或已验证内容。 |

不建议用小号给主号刷量、刷评论、导流。这会带来平台和声誉风险。

## 客户账号风险

如果甲方把账号交给我们运营，需要提前考虑：

- 优先使用平台正式授权，不共享密码。
- 客户保留所有权和管理员权限。
- 明确谁有最终内容审批权。
- 明确账号封禁、删帖、警告和申诉由谁负责。
- 明确合作终止后的数据、粉丝、帖子和询盘归属。
- 明确历史违规账号的责任边界。
- 明确我们是否能使用账号数据做匿名汇总学习。

建议账号字段：

```text
account_id
platform
handle
owner_type = SELF / CLIENT
owner_client_id
authorization_type
authorization_expires_at
browser_profile_id
proxy_region
target_region
language
account_status
risk_status
daily_publish_limit
content_approver
service_owner
notes
```

## 红线

- 不把多客户共享账号伪装成单一品牌号。
- 不跨客户泄露产品资料、询盘和联系方式。
- 不把一个共享账号的全部数据重复算给多个客户。
- 不做绕过平台验证的自动化。
- 不靠运营人员记忆来管理账号归属。
